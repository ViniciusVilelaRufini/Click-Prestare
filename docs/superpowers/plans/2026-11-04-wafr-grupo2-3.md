# WAFR grupos 2-3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Zerar os 7 HRIs restantes do WAFR com mudanças reais e reenviar o FTR.

**Architecture:** API NestJS pronta para várias instâncias (lock de crons, bulkheads), segredos no SSM, arquivos em bucket privado com KMS e link assinado; infra com RDS Multi-AZ em sub-rede privada, EB com ALB em 2 AZs atrás do CloudFront.

**Tech Stack:** NestJS/Prisma (MySQL), AWS SDK v3, Elastic Beanstalk, RDS, S3, KMS, SSM, Organizations, IAM Identity Center.

**Spec:** `docs/superpowers/specs/2026-11-04-wafr-grupo2-3-design.md`

## Global Constraints

- Nenhuma env var nova no EB (limite 4096); valores podem mudar ou sair.
- Toda dependência nova da API entra pinada em `click-cond-web/scripts/migration/bundle-eb.mjs`.
- Deploy = push em master e main; conferir EB verde + canary PASSED depois de cada mudança.
- Bucket antigo `storage-click-dev` (conta 952520388262) nunca é alterado nem apagado.
- Dev local sem AWS precisa continuar funcionando (loader de segredos e lock tolerantes).

## Review Focus

- Duas instâncias executando o mesmo cron ao mesmo tempo → só uma executa (Task 1).
- SSM indisponível no boot → API sobe com o env existente e loga aviso (Task 2).
- Arquivo antigo com URL pública do bucket velho depois da migração → continua abrindo (Task 3).
- Link assinado expirado/forjado → 403, nunca objeto de outra pasta (Task 3).
- Instância removida pelo ALB no meio de uma requisição → cliente recebe erro tratável, não dado corrompido (Task 1).
